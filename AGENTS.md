# Agent guide

k8schema is the Kubernetes API as PHP classes (namespace `K8Schema\`), generated by
k8schema-generator. `main` holds the template and the *Generate* workflow; every Kubernetes minor
lives on its own branch (`v1.35`, …) with the generated `src/`. This file is for coding agents;
[CONTRIBUTING.md](CONTRIBUTING.md) says the same for people, and where the two differ,
CONTRIBUTING.md wins.

## What a pull request must satisfy

- It targets `main`, never a minor branch and never the branch of another open pull request.
- It never edits generated classes by hand: a wrong class is a change to k8schema-generator, which
  every minor picks up on its next regeneration.
- The pull request's run of the *Generate* workflow passes (a dry run over the supported minors:
  every file compiles, the tree autoloads and serializes a `Deployment`, the code style is clean).
- No job that a pull request can start names a stored secret; only a job-level `if:` keeps a secret
  off a job. `.github/scripts/pr-job-secrets.test.sh` and the workflow's `pr-secrets` job check it.
- The title and every commit are [Conventional Commits](https://www.conventionalcommits.org)
  (`type(scope): subject`); each commit has a body that says what changed and why. Pull requests are
  squash-merged: the title becomes the commit on `main`.
